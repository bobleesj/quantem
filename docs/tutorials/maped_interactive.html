01What moves through one seven-tilt run?

MAPED has one scientific sequence. The input files become GPU-resident encoded count streams, summary images measure the common origin, alignment finds the row-column shifts, and the merge visits bounded regions. The output is globally scaled to uint16 and reopened in packed form for inspection.

Read the picture. The seven small source cards remain available through both merge passes. Only the active bounded region becomes a temporary working tensor.

02What do the alignment parameters mean?

Each tilt sees the same specimen through a slightly different origin and scan offset. MAPED first measures a mean diffraction pattern, then a mean bright-field image, then estimates shifts. The controls below change the measurement choices, not the scientific sequence.

M(r,c) = [1 ⁄ number of scan positions] ∑ D(r,c,i,j)
M is the mean diffraction pattern used for the common origin. The same idea gives the mean bright-field image over detector rows and columns.
Why the controls affect different measurements

sigma sets the smoothing scale used while finding the diffraction origin. edge_blend softens the boundary of each shifted region so a block edge does not become a false feature. num_iter repeats the real-space shift refinement. The public method sequence stays preprocess, diffraction_origin, diffraction_align, and real_space_align.

merged(r,c,i,j) = ∑t wt Dt(r + Δrt, c + Δct, i, j) ⁄ ∑t wt
Takeaway. A parameter is useful when its visual effect matches its job: smoothing changes the origin estimate, edge blending changes block boundaries, and iterations refine scan shifts.

03Why all seven tilts fit a 24 GB laptop

The resident representation is encoded, so the seven inputs occupy about 7.76 GiB in the qualified CUDA run. MAPED never creates the complete 36 GiB float32 merged tensor. It measures the global range in one pass, then merges and encodes row-aligned regions in a second pass.

peak ≈ encoded inputs + bounded region + allocator overhead
Region size changes temporary workspace. It does not change the logical output size, and it does not force a float32 copy of the entire merge.
What the bars estimate

The illustration uses 1.108 GiB per encoded tilt, 192×192 detector pixels, four bytes for a temporary float32 region, and a fixed planning allowance for allocator and summary tensors. The measured CUDA reference is 11.15 GiB process peak and 12.08 GiB total GPU0 at seven tilts and 4,096 frames per region. The bars are a planning model, not a replacement for a hardware receipt.

On a 24 GB machine. Keep all seven encoded sources resident, use the bounded region path, write the scaled output, release the MAPED-owned sources, and reopen selected regions for the viewer.

04How global scaled uint16 keeps the science visible

The merged values are computed in float32, then one global scale and offset describe the complete output. Every stored uint16 code maps back to the same physical intensity units. This keeps tilts comparable and lets the viewer read small regions without loading the full logical array.

q = round((x − offset) ⁄ scale),   x̂ = offset + q · scale
scale = (global maximum − global minimum) ⁄ 65,535. The restored value x̂ differs from x by at most half a code step before any storage compression.
What the precision receipt records

The saved result records storage type, source dtype, complete output range, scale, offset, RMSE, maximum absolute error, and clipped count. In the qualified CUDA output the RMSE was 0.006951, maximum error was 0.01318, and clipped values were zero.

Display rule. Float32 is the compute reference. Globally scaled uint16 is the compact display and interchange representation. Show4DSTEM reads the packed result by selected region.

05The public API and the parameter map

The scientist-facing call remains short. Encoding, hot-pixel correction, bounded reads, range measurement, and packed reopening are selected by the loader and merge infrastructure. MAPED keeps the alignment and merge sequence visible.

from quantem.diffraction import MAPEDTorch

maped = MAPEDTorch.from_files(files, device="cuda:0")
maped.preprocess(plot_summary=False)
maped.diffraction_origin(sigma=1, plot_origins=False)
maped.diffraction_align(edge_blend=2, plot_aligned=False)
maped.real_space_align(num_iter=20, padding=2, edge_blend=5,
                       pad_val="median", shift_method="bilinear")
merged = maped.merge_datasets(save_to="merged_master.h5", plot_result=False)
viewer = maped.show()
